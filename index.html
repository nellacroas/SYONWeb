Why SYON?

      
Designed from first principles to eliminate every ambiguity in modern configuration files.

    


    

      

        JSON Superset + Patching
        
Drop in existing JSON, then patch it with ---

        

          Start a document with a standard JSON object or array, place a --- patch boundary, and extend it with headings, dotted fields, array appends, or tables—without rewriting the original JSON structure.
        

        
{
  "service": "payment-api",
  "settings": { "timeout": 30 },
  "ports": [8080]
}
---
// Extend the JSON root in a new patch:
settings.retries: 3
ports[+]: 8443

# settings.tls
enabled: true

      


      

        Comments Everywhere
        
Real // comments—even inside inline JSON objects

        

          Unlike JSON, SYON treats // line comments as first-class syntax everywhere: after headings, on table rows, and right inside multi-line { … } objects and [ … ] arrays.
        

        
# client
request: {
  method: "POST", // trailing comment inside an object
  // retry policy for transient 5xx responses
  retries: 3,
  headers: {
    "X-Env": "staging", // trailing commas are welcome too
  }
}

      


      

        No Indentation Traps
        
Headings move the cursor. Fields write values.

        

          In SYON, indentation is purely cosmetic. # and ## headings navigate the object tree, while dotted fields like database.host: "localhost" allocate intermediate objects without closing navigation scopes.
        

        
# application
database.host: "localhost"

## database
pool: 5
timeout: 30

# endpoints[+]
path: "/health"
public: true

      


      

        First-Class Tables
        
Schemas (*), group locks (^), and omission (_)

        

          Define array-tuple tables (+) or object-map tables (- key :). Row 2 locks group-identity columns with ^, _ omits optional fields, and *** starts a fresh group.
        

        
routes[]
* name      | port | tls  | note
+ "primary" | 443  | true | "Main ingress"
+ "backup"  | ^    | ^    | _
***
+ "legacy"  | 80   | false | "Redirect only"

      


      

        Write-Once Safety
        
Catches duplicate keys & accidental overwrites

        

          Silent key overwrites are a top cause of production outages. SYON prohibits duplicate field assignments across the entire document and seals completed container literals until the next --- patch boundary.
        

        
settings: { timeout: 30 }
---
settings.enabled: true    // Valid: adds a new sibling field
// settings.timeout: 60   // Error (E_DUPLICATE): already assigned!

      


      

        Multiline Strings & Continuation
        
Literal '…', escaped "…", & multi-line > blocks

        

          Use 'single quotes' for literal backslashes, "double quotes" for escapes, and > blocks to write real multi-line strings or join '…' and "…" fragments across lines.
        

        
// 1. Multi-line string spanning > lines (preserves \n):
script: >
> "echo 'Starting deploy...'
>  ./bin/run --env=prod
>  echo 'Done!'"

// 2. Join literal '' and escaped "" across > lines:
logPath: >
> 'C:\Program Files\SYON\'
> "logs\t(v0.1)"
