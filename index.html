SYON Synthesized Object Notation

Structured data, written like a document.

SYON borrows the feel of Markdown: headings give structure, tables hold repetitive records, and inline objects and arrays fit naturally alongside them. Each file describes one data tree, with explicit types and clear errors for conflicting assignments.

Designed for files people edit by hand

      
Readable like a document, with explicit structure and predictable rules. SYON keeps hand-written data easy to scan, and makes sure every file has exactly one meaning.

    


    

      

        JSON Compatible
        
Use familiar inline objects and arrays

        

          Any JSON object or array is already valid SYON. Add // comments and line breaks inside containers to annotate existing data—no rewrite required.
        

        
{
  "service": "payment-api",
  // comments can sit alongside fields
  "settings": {
    "timeout": 30 // and trailing comments
  },
  "ports": [8080, 8443] // arrays too
}

      


      

        Headings & Appends
        
Structure comes from headings, not indentation

        

          # and ## choose where the following fields go, just like sections in a document. tags[+]: appends a value, and ## replicas[+] starts a new object in an array. Indentation is purely cosmetic—indent for readability, or keep everything flush-left.
        

        
# database
host: "db.internal"
tags[+]: "primary"
tags[+]: "ssd"

    ## replicas[+]
    region: "eu-west-1"
    readOnly: true

    ## replicas[+]
    region: "eu-central-1"
    readOnly: false

      


      

        Sections (---)
        
One document, many sections

        

          A --- line does not start a separate document. It only resets the heading cursor back to the root; everything after it still builds the same data tree. That lets one section describe one complete piece—a service, its route, and its settings—even when those land in different parts of the tree.
        

        

          Adding something new means adding a section, which keeps edits local and diffs easy to review.
        

        
# gateway
name: "edge"
---
// auth service
# gateway
routes.auth: "/auth/*"
## services[+]
name: "auth"
image: "auth:1.8"
---
// billing service
# gateway
routes.billing: "/billing/*"
## services[+]
name: "billing"
image: "billing:3.1"

      


      

        Write-Once Safety
        
Sections can extend each other, never overwrite

        

          Because every section writes into the same value, SYON keeps one assignment history for the whole document. A later section may add new fields or append to arrays, but a field assigned anywhere else is an error that points to both lines—not a quiet overwrite.
        

        

          Within a section, a completed {…} or […] literal is also sealed, so it can't be extended by accident until the next ---.
        

        
# service
settings: { timeout: 30 }
ports: [8080]

---
# service
settings.enabled: true  // ok: a new field
ports[+]: 8443          // ok: append to the array
settings.timeout: 60    // error: already assigned

        
[E_DUPLICATE] Line 9: Duplicate assignment at "service"."settings"."timeout".
              First assigned at line 2.

      


      

        Tables
        
Repetitive records fit in a table

        

          Declare the column schema once with *, then write one record per row with +. The second record row fixes which columns use ^ to copy the group's first row; every later record row must keep that same ^ pattern. *** starts a new group. A complete + ~ row appends a null array element—for example, a missing sensor reading.
        

        
readings[]
* sensor   | celsius
+ "indoor" | 21.5
+ ^        | 21.7
+ ^        | 21.6
***
+ "outdoor" | 12.4 
+ ~ // append a null to readings
        

      


      

        Keyed Tables
        
Tables for named entries, too

        

          Start rows with - key : to build an object instead of an array. With * $, each key maps straight to a single value—handy for writing a long string once and reusing it with ^.
        

        
# endpoints
* $       : method | path       | rateLimit
- health  : "GET"  | "/health"  | 60
- metrics : ^      | "/metrics" | 120
***
- charge  : "POST" | "/charge"  | 60

# notices
* $
- web    : "Maintenance starts at 02:00 UTC. Please save your work."
- email  : ^
- mobile : ^

      


      

        Explicit Values
        
What you write is what you get

        

          Strings are always quoted; only numbers, true, false, and null are written bare. Unquoted text is never reinterpreted, so every value's type is visible right in the source.
        

        
region: "eu-west-1"
replicas: 3
enabled: true
fallback: null

      


      

        Strings
        
Literal and multiline strings

        

          Use 'single quotes' for literal text, including backslashes in file paths. A > block lets a string span multiple lines while preserving its line breaks.
        

        
path: 'C:\data\readings.csv'

// One space immediately after > is ignored, so you can align the text.

message: >
>"Deployment started.
> Checking services.
> Deployment complete."

      

    

  


  

    

      

        Data Export
        
Tabular data, with types and structure

        

          Tables make SYON a compact way to export and exchange records—for example, database exports that stay readable and preserve the structure needed for re-import.
        

        

          Compared with a plain CSV file, each cell keeps its value type: numbers stay numbers, true stays a boolean, and arrays or objects fit in a single cell. When flattening an array of objects with different fields, _ leaves a field absent rather than writing null.
        

        

          Dotted columns such as customer.name rebuild nested records. If all stock.* cells are _, the stock object is absent too—not an empty object. ^ avoids repeating shared group values, and several tables plus their metadata can live in one file.
        

      

      
# export
source: "shop_db"
exportedAt: "2026-11-14T09:00:00Z"

orders[]
* customer.id | customer.name  | orderId  | total | paidAt                 | items
+ 101         | "Ada Lovelace" | "A-1001" | 42.5  | "2026-11-02T10:15:00Z" | ["book", "pen"]
+ ^           | ^              | "A-1002" | 18    | null                   | ["ink"]
***
+ 102         | "Alan Turing"  | "A-1003" | 120   | "2026-11-03T08:40:00Z" | ["lamp"]
+ ^           | ^              | "A-1004" | 7.25  | _                      | []

products[]
* sku     | name   | price | stock.warehouse | stock.qty
+ "BK-01" | "Book" | 12.5  | "LON"           | 240
+ "PN-02" | "Pen"  | 1.2   | _               | _
